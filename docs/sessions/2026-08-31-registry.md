## Task 1 — BACKLOG 514: the CI gate (`rehearse (worst, seed 1)`, red 5 consecutive runs)

**The filed title is wrong in both halves, and the fix it asked for would not have worked.**
514 says a cron "OVERWROTE a notes cell" and asks for the write path to go through
`pipeline/notes.py` and the lost verdicts restored. Reproduced byte-for-byte from the
shipped code (the run's headSha `d6408ca` is identical to origin/master for every file
involved):

1. **Nothing overwrote anything.** `bd_rescue.py:343` rebuilt `Israel Opera`'s row and its
   87-char paid verdict took the cell over `notes.py`'s 220 cap, so `append` evicted the two
   **unprotected** history segments (`queue-hunt`, `listing-hunt`) — through `notes.py`,
   exactly as designed. The `token` column gaining a copy of the url is `bd_rescue`'s row
   rebuild and is cosmetic: no pool or invariant reads `r[2]` on a scrape row, and 376 rows
   already carry it.
2. **The red is the opposite direction and involves neither evicted segment.** Retry's *new*
   segment `retry 2026-08-31: scanned; no open Israel roles now` **added** the row to
   `validate_empty`'s pool (membership is that literal substring, `validate_empty.py:42`),
   and retry's own `replace_own("retry", …)` deletes the phrase's sole carrier the next
   night. A one-night pool membership, which `rehearse_registry.py:354` correctly calls a
   loss — `validate_empty` has no `_OWN_STAMP` exemption, and should not have one: the tool
   that re-checks empties is not the tool that writes the emptiness.

**The rule that was missing** (now `ARCHITECTURE.md` §2, "a fact another pool selects on"):
the existing rule forbids a *pool* standing on a token inside another tool's segment
(BACKLOG 320). The mirror binds the *writer*, and nothing stated it: when your own segment
is the only carrier of a fact another pool selects on, `replace_own` deletes that fact every
night you re-stamp. You break no rule — it is your own segment — and the row silently leaves
a pool. §2 also mis-filed `validate_empty` under "fact pools ... cannot erode"; corrected to
a hybrid, which is how it eroded.

**The fix.** `retry_unreachable._fold_empty` carries the dated fact forward:
`retry <today>: still unreachable; no open Israel roles <date0>`. Two true dated facts,
never a claim of a fresh scan; `date0` is re-extracted each night so it cannot accumulate;
the moment a retry reaches the page the `empty` branch writes its own fresh phrase and the
fold state dissolves.

**The guard beside it is not optional, and this is the part a first pass would have
shipped broken.** The folded segment is ~33 chars longer, and `replace_own` DELETES before
it appends. `notes.append` drops a newcomer whole on a saturated all-protected cell — a
guarantee written for a tool that only ADDS — so the pair can delete a fact and then fail to
write its replacement. Measured against the real registry: 19 rows carry the phrase in their
own retry segment; the fold fits on 18; **`Syte`** (208 chars, 4 of 4 segments protected)
would lose *both* the phrase and this tool's stamp. `_keep_selectors` compares the candidate
cell against the one it holds and keeps the old note if a selector went missing — costing
one saturated row tonight's date, which is the trade `notes.append` already makes. Writing
the short unfolded segment instead is **not** a fallback: on a Syte-shape without a second
membership token it deletes the phrase's only carrier just the same.

**Row repair.** `listing-hunt 2026-08-29: not a listings page; no listing found` restored via
`notes.append` (153 → 218). **`queue-hunt` is not restorable and the next session should not
try**: at 218 the only unprotected segment is the restore itself, so `append` evicts it to
make room and then drops the newcomer too — measured result, the cell back at 153. Attempting
the second restore *costs* the first.

**Evidence.** `rehearse --nights 14 --policy worst --seed 1`: `validate_empty` 65 → 64 on
night 1 before, flat at **65 across all 14 nights** after, 0 orphans throughout. Both new
guards were proved able to fail by reverting each half of the fix in source: no-fold kills
both tests, no-drop-guard kills the guard test. Both mutation records report `killed`.

## Task 4 — the drain's alarm could not see the failure it names

The `out/` fix (`queue_resolve_search.py:500`, `df803a1`) **is** on origin/master and carries
a test; the cloud key is armed (repo secrets set 08-20, and today's digest bought
`unlock_calls=86` from Actions). So the remaining work was the stamp — and the stamp was
blinder than the brief said:

**A disarmed key never reaches the IDLE alarm at all.** With no key
`deep_validate.google_via_unlocker` returns `[]` in silence → `search_one` calls it
`no-search-results` → `queue_state.ingest` records a dated attempt. A fully disarmed night
therefore writes ~112 confident refusals, `searched_recently` reads like a working drain,
the IDLE branch (`selectable and not searched`) never fires, and `tried_within(…, 14)` locks
every one of those names out for a fortnight on a measurement nothing made. That is CLAUDE.md
rule 2 with a paid rung on the other side of it.

Both discriminators were already on disk and unread:

* **`queue_resolve_search._refuse_to_run_disarmed`** — refuses before `ranked_targets()`, so
  nothing is selected and nothing recorded; unrecorded names stay never-searched and sort
  first tomorrow. Reads `DEEP_BD_SEARCH_CAP` exactly as `deep_validate` does, because cap 0
  short-circuits before the key is looked at and is indistinguishable downstream.
* **`queue_pipeline._drain_liveness`** — `empty_search_share` published every night
  (healthy **0.5 %**: 7 of 1,463 attempts 08-29..31; live reading today **1.2 %**; disarmed
  100 %), `queue drain BOUGHT NOTHING` at ≥90 % over ≥10, and when nothing was searched,
  `cloud_state/bd_spend.jsonl` splits "bought and died" from "never started" — the four dead
  shards of 08-30 each left a `credits:1` line, and a keyless shard leaves none because it
  never spends. A partial cap exhaustion lands at 25-50 % and is deliberately *below* the
  alarm: visible in the share, no wolf cried.

All four states were driven end-to-end and print distinct strings; a healthy night stays
silent.

**Cost this bought.** My preflight broke two of my own lane's offline drain tests, which
drive `main()` with a stubbed `search_one` in a keyless environment. They now declare the
rung armed with a dummy key (`tests/conftest.py` bans the transport, so nothing can be
bought). That is a real new obligation on any future test that drives `main()`, and it is
recorded in §2 rather than left to be rediscovered.
