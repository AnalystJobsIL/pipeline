`country_code` is stamped **`IL` unconditionally** (operator answer 3), vetoed only by a
foreign place the card's own text states. Admit-only, the `_sf_country` asymmetry: a code is

have dropped the 10 cards with no cell and left 36 more to a vocabulary that cannot read
`גוש דן`. `undated = True`: the cards publish no date, so `health.abandoned` can never judge
a board read this way, exactly like Comeet and Jobvite — noted as a risk, not fixed. Not
`israel_scoped`, so an empty read is evidence.

**The vouch, and why a query-string tenant is safe to declare.** No gate reads a query
string: `checkable_token`, `tenant_is_this_company` and `_slug_candidates` read subdomain

* `identity_facts.DECLARED["Harel Insurance & Finance"] = {"tenants": ("harel",)}`. Measured:

## 2. A regression is two consecutive nights (`606`)

`health.stale_reason` returned `regressed-to-zero` on ONE reading, `mail_lines` announced it
under `new:` that morning and `cleared:` it the next. Re-derived from
`git show <sha>:cloud_state/stale.json` over the 14 nights to 2026-09-18, **one snapshot per
date** (18 commits, 14 dates — the collapse matters: counting commits instead gives 30
one-night runs where the nights give 44):

| | |
|---|---|
| runs of `regressed-to-zero` that BEGAN inside the window | **81** |
| of those, exactly one night long | **41 (51 %)** |
| suppressed by N=3 instead | 54 of 81 (67 %) |
| names that entered the class ≥ 2 separate times | **20** (≥ 3 times: 8) |
| the worst | IRP Systems 4, Workiz 4, Axioma 4, then Adi Il / Exyte / Keter / Siemens DIS / Sternum 3 |
| of the 20, NATIVE rows | **2** — DoubleVerify (greenhouse), Swimm (comeet) |

The mechanism behind the scrape half is not ours: on each of IRP Systems' four flagged
nights its rot entry reads `why: empty, found 0, http 202` — a 202 interstitial booked as an
empty page — and the 202 class spikes on exactly those nights (**10 / 10 / 12 / 12** names on
09-08 / 09-11 / 09-14 / 09-16, against 1 on every other night; 18 distinct names over the
fortnight). Four of the seven names overlapping the new-regression list on each spike night
are 202s. That is `scraper`'s, filed with the numbers, not fixed here.

The change is one field and it gates the MAIL only:

* `health.record` reads the previous `stale.json` itself and writes `nights` + `last` on every
  entry — previous same reason → +1, else 1, and **never a bump when `last` is already
  today**, because the digest AND the Monday self-heal both commit this file (4 of the 18
  snapshots were a same-date re-write, and the two writers together would otherwise reach the
  threshold inside one morning). A `write=False` caller (a scoped run) does not read the file
  and does not write the fields: the streak belongs to the committed file, and reading
  cron-rewritten state is what `tests/live_state.py` refuses — it caught this immediately.
* `REGRESSION_NIGHTS = 2` (answer 2). N=3 rejected on the number above: +13 suppressed for a
  second night's delay on every true regression.
* `_announce` replaces the "is the reason new" test for this one reason: announce on the
  morning the streak REACHES 2, and never twice. `cleared:` skips a row that left below 2 —
  it was never announced, so its disappearance is a recovery from nothing. `_watchful`
  re-keys the rest for the STANDING line as a quiet `k watching (first night)`.
* `stale_reason` is untouched and the ROW still enters the file on the first reading:
  `resolve_broken.candidates` and `discovery_daily`'s targeted rotation read that flag and
  neither may lose a row because the mail is not ready to name it. Which is precisely why
  those two still act on a one-night reading — `635`, `infra`'s, with the diff and the
  numbers (Workiz at **4** of 5 strikes; Dell, Highcon, SMARTECH struck on one night).
* `_nights_of` defaults a missing field to **REGRESSION_NIGHTS, not 1**. Yesterday's
  `stale.json` has no such field and neither does any older test's hand-built entry; reading
  "cannot tell" as "first night" would have suppressed the whole standing class on the first
  morning of the new code. Suppressing a real regression is the expensive direction —
  `_fetched_none` states the same rule for recoveries.
