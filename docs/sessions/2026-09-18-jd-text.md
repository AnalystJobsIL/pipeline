## C1 — the rule: own-board chrome renders twice

The full argument and every rejected alternative is in `ARCHITECTURE.md` §7a, *Own-board chrome
renders TWICE*. In short: `jdfill.mirrored_nav(text, k=NAV_K)` finds a run of 8 marker-free
tokens rendered BOTH above the posting (inside `HEAD_WINDOW`, before the first `_JD_MARKERS`
hit) and below it (after the last). The tail half joins `furniture_at`; the head half joins
`strip_head`, which now takes `whole=` because `jd_body` has already deleted the footer copy
the rule recognises the menu by.

**Why the closure sentence had to be given back.** The 587 line sits at offset 0 of a stored
text — ABOVE the head menu — so the mirror's head cut is the first rule in this module that can
reach it (`_HEAD_FURNITURE`'s markers are the page's own header and are long gone by the time
text is stored). `strip_head` now ends with `with_closed_line(t, body)`: a cutter may cut, and
the one line the store is not allowed to forget comes back on top.

**The listing-card veto.** `_is_listing_card` refuses a text carrying two DISTINCT Material
Symbols ligatures in its first 400 characters. 21 of 2,421 bodies, every one a Google Israel
results card, 0 elsewhere — and those 21 are the only rows in the whole corpus whose
`looks_like_jd` verdict this commit changes.
