## What changed

**`pipeline/jdfill.py`** — the gate, the second parser, the counters:

- **`unfillable(url)`** names host families no rung we own can read: `indeed.com` (401/403 on
  **22 of 22** job URLs sampled, `reject_authwall` to the Unlocker) and `secrethunter.io` (a
  **byte-identical** 33,495-byte JS shell — 776 characters of text — for **5 of 5** different job ids). Matching is exact host or subdomain,
  parsed — deliberately **not** `aggregators.is_aggregator`, which lists `linkedin.` (91 of the
  110 inline fills) and whose regex matches `indeed.com.evil.co` (verified). Ordered **after**
  the native rung, so a future reader for a blocked host makes the entry dead rather than
  harmful, and **one refused URL per run is fetched anyway** so the refusal stays falsifiable.
- **The gate moved above `plain_fetch`** for all three callers. It used to guard only Bright
  Data, so an auth-walled host and a search page each cost a 15-second inline fetch every
  morning and were booked as *failed fetches*; and a listing page whose GET timed out was
  stamped `transient` and re-fetched daily for ever.
- **`is_job_url`** refuses a URL with no digit in its path whose last segment is a listing word,
  or which ends `.html`, or whose query is a filter with no id. Equality on the last segment,
  never substring — though only from three path segments up: `/en/jobs/senior-data-analyst-jobs`
  is a posting, while a two-segment `/jobs/senior-data-analyst-jobs` is refused by the older
  segment-count rule underneath it.
- **`jsonld_jd(body)`** reads the page's own `<script type="application/ld+json">` and returns
  its `JobPosting.description`. A **parser, not a rung**: it runs on the body
  `plain_fetch` already returned *and on the body Bright Data was already charged for*, only
  after `extract_jd` found nothing. `JobPosting` nodes only — never `Organization`/`WebPage`,
  which is the "About <company>" blurb. Bounded scan/blocks/block-size. `via` still names the
  fetch that paid; the parser is named by the reason (`ok-jsonld`).
- **`JD.native`** carries the native rung's failure reason, so `phenom shell/workday-http` no
  longer reads as "Workday pages are shells, as always" — which is how the next item was found.
- **`native_url` drops a trailing `/apply`**: `fetch_phenom` emits Workday URLs of that shape
  (GE HealthCare, 23 Israel postings a day) and the cxs endpoint 404s on the suffix. Measured
  live: 404 with it, **200 and 2,865 characters** without.
- **`Unlocker`**: `capped` is now a flag (an exhausted allowance could not alarm), and a run
  that worked once and then failed `breaker × 4` times in a row opens the breaker
  (`failing-after-N`). The account-level rule (`no-success-after-N`) is unchanged — a short
  failing streak after a success is still not an outage, which was pinned on 08-24.
- **`run_backfill`** counts `todo`, `probe`, `jsonld`, `native:<why>`, and splits
  `skipped_budget` into `skipped_cap` / `skipped_clock`; **`why_string`** turns the reason
  histogram it always built and always discarded into `no-markers2+timeout1`.
- **`alarm_for`** gained the states that could not fire: `bd-spent(N calls, 0 filled: …)`
  independent of `tried` (the 10-attempt mass-fail rule is structurally dead on the matched
  driver at 130/135 coverage), `bd-capped`, `jd-nothing-attempted` (only when there WAS work —
  a driver with an empty todo and a day where everything is cooling stay silent), and
  `jd-budget-spent`.
- **`record_enrich`** SUMS numeric counts on a same-day re-stamp and records `<driver>_runs`; a
  crash report no longer erases the day's counts, and yesterday's alarm is not re-announced.
- **`stamp_path_for`** compares by `os.path.realpath` and builds with `abspath`:
  `--cache ./scraped_cache.json` used to divert the stamp (the mail then said
  `no-report(scrape)` about a healthy driver), and a bare relative target killed the driver in
  `os.makedirs("")` *after* the credits were spent.
- **`JDFiller`** measures **seconds spent fetching**, the shape `seniority.Classifier` uses one
  line away in `run.py` — it was wall clock from construction, which is before the 870-board
  fetch loop (5.7 of 25 minutes gone before a single fill). `JDFILL_TIME_BUDGET_MIN=0` now
  attempts nothing (it meant *unbounded*, the opposite of `run_backfill`'s pinned rule), and
  `JDFiller(budget_min=0)` no longer silently becomes 20. A spent budget is an alarm, not a
  step-log line.

**`enrich_matched_jd.py`** — three passes and a live-role filter:

- **The cache rung**: for a row still short, read the text we ALREADY hold for another of
  that role's own addresses. **Zipher: 170 → 2,021 characters, 0 requests, 0 credits.** Two
  identity gates, because `seen_ids` is not a list of a role's own addresses: the cache entry
  must be filed under this company, and `roles.names_in_url` must positively name it.
- **The canonical fetch** is unchanged. The fetch-the-siblings pass that was in the plan was
  **deleted in wave 1**: 0 measured yield, and it would have published another employer's
  description under this company's name (see the waves below).
- **Closed and superseded rows are skipped.** The ledger (`cloud_state/roles.jsonl`) is the
  authority; `COALESCE(status,'') != 'superseded'` is the SQL half (a bare `!=` is NULL for
  every NULL row and would select nothing). An unreadable ledger **filters nothing and alarms
  `ledger-unreadable`** — the first version fell back to `last_seen`, and a test showed that
  would disable the whole driver after any outage longer than three days.

**`enrich_scrape_jd.py`**: `_todo` dedupes by URL (8fig and SuperMeat each contributed the same
listing URL twice) and treats `< MIN_DESC` as missing, agreeing with the other driver at last;
it counts and stamps what its gates dropped.

**Caps cut**: `JD_ENRICH_BD_CAP` 400 → 40, `MATCHED_JD_BD_CAP` 250 → 25. Measured need over the three preceding days: 7, 0, 1 (scrape) and 4, 2, 3 (matched).
