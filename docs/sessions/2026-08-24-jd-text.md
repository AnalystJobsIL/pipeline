## What changed

**`pipeline/jdfill.py`** is now the library (was: an inline filler that lazily imported a root
script, which imported `bd_rescue`, which imported half the registry ladder):

- `fetch_jd(url, bd=None, company="")` — native JSON → plain HTML → Unlocker. Returns
  `JD(text, via, reason, transient)`. Reasons: `ok · no-url · not-a-job-url · shell ·
  no-markers · http-NNN · timeout · bd-unavailable · bd-capped · bd-<x-brd-error-code>`.
- `native_url(url, company)` decides the rung from host + path alone: Workday cxs,
  SmartRecruiters postings API, BambooHR `/detail`, comeet.com embedded sections, Greenhouse
  by board slug (registry token → name → host label) incl. `?gh_jid=` embeds. Live
  (`smoke.py`): Workday 4,616 chars in 0.8 s, Comeet 4,334, Greenhouse/Nebius 6,000,
  SmartRecruiters 2,799, BambooHR 3,192; Taboola's `gh_jid` 404s on its own board (the role
  is stale) and falls to HTML → `no-markers`; Meta's search page → `http-429` and
  `is_job_url` = False.
- `Unlocker`: 401/402/403 from the API or no key ⇒ `unavailable`, no further requests; a 200
  with `x-brd-error-code` ⇒ that URL's failure; breaker after 5 consecutive failures with no
  success. `used` counts requests sent.
- `is_job_url` — a search/list URL never reaches the Unlocker (the 4 wasted credits).
- `due()` / `stamp_value()` — one cooldown rule for both drivers (they used `>` and `<=`,
  complements, untested); `YYYY-MM-DD transient` retries after 1 day, a bare date after 7.
- `run_backfill(items, save=…)` — the loop both drivers used to reimplement; `alarm_for`.
- `record_enrich(alarm, **counts)` — union-merges into today's `enrich` stamp; with no
  arguments it only writes `alarm=no-report` when nothing was stamped today.
- `JDFiller` keeps its gates; adds `by_platform` (platform × reason), `alarms()`.
- `load_secrets()` lifted from `run.py`; the drivers import nothing from the repo root
  (`test_jd_text_imports_no_root_module`).

**Drivers**: `enrich_scrape_jd.py` (`--cache PATH`, `--dry-run`, atomic write with the same
bytes as before, re-exports `extract_jd`/`html_to_text`/`_plain_fetch`/`_JD_MARKERS`/…),
`enrich_matched_jd.py` (`--cooldown-days`), both stamp `alarm=crash:<Exc>` (beside a copy target, never the real file) and re-raise.
