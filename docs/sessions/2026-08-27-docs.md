# 2026-08-27 — `docs` lane: a number a doc states is now a build artifact

## The finding the whole session turns on

`docs/check_docs.py` was green — `0 error(s), 0 warning(s) over 31 documents` — while three
Opus attackers reading those same documents against the tree found **46 measured
contradictions**, four of them material enough to change what a reader would do.

The linter proves that what a sentence *points at* exists. It has never been able to prove
that a sentence is *true*, and it says so in its own docstring. The gap is not a bug; the
gap is the entire failure mode this documentation set was arranged against, and it had been
left to goodwill.

The repo had already run the experiment that says what to do about it. `git log -S` dates
it: commit `8f049f2`, *"Make the docs a build artifact that can go red"*, introduced **both**
`check_continue_on_error` **and** the sentences "846 companies" and "433 through a native ATS
API". Four days later the machine-checked number was still exactly right and every hand-typed
one was stale. `~1,200-row` — a bracket — entered `README.md` on 2026-08-24 and is still true
at 1,244. `ARCHITECTURE.md:361` carries its own recompute command inline, has been corrected
by three different lanes, and is correct today; `ARCHITECTURE.md:37` states the same fact with
no command and said 16.

**Machine-checked numbers survive. Brackets survive. Numbers next to their command survive.
Bare point numbers in ASCII boxes died — all six of them.**

## What shipped

### 1. The derived-fact registry (`docs/check_docs.py`)

`check_continue_on_error` generalised into `FACTS`: ten registered numbers, eighteen sites,
in two classes split by **who moves the number**.

**EXACT** — moves only when an agent commits a code change (`len(FETCHERS)`, the root-module
count, the unreferenced-module count, the no-`__main__` count, the continue-on-error ratio).
Equality is the right contract and red is the right colour: the person who can fix it is the
person pushing.

**CENSUS** — moves because eight crons ran. Replayed from git, one snapshot per day:

```
2026-08-21 total=1170 active=530 scrape= 98 api=432
2026-08-22 total=1189 active=754 scrape=290 api=464   +224
2026-08-23 total=1209 active=862 scrape=428 api=434   +108
2026-08-24 total=1229 active=877 scrape=440 api=437    +15
2026-08-25 total=1241 active=870 scrape=438 api=432     -7
2026-08-26 total=1244 active=875 scrape=439 api=436     +5
```

An equality check on `active_rows`, seeded on the day the docs were written, **would have
been red on 3 of the next 3 days**. A census site therefore may not carry a bare point number
at all. It carries `~900` or `850-950`, and **the precision the author writes is the tolerance
they are claiming**: `~1,200` claims hundreds, `~870` claims tens. There is no tolerance
constant anywhere in the file — the notation English already uses is the machine-readable
contract.

The range form was added because a bracket's headroom depends on where in the bracket you sit,
and this was not hypothetical: on 2026-08-27 the registry was 1,244 against `~1,200`, **five
rows** from red, and API rows were 451 against `~500`, **one row** from red.

**`api_rows` and `scrape_rows` are deliberately NOT registered.** Between `ae6eeae` and
`623b2a9`, about an hour apart today, the split went 436/439 → 451/421 — eighteen rows, in an
hour, with no doc edit and nobody pushing who could have known. Moving a row between those two
buckets is the registry lane's entire job. Those sites carry the command instead. Registering
them would be registering the wrong thing.

**A latent bug in the prior art, fixed by the move.** `check_continue_on_error` iterated
`DOC_GLOBS`, which includes `docs/sessions/` and `docs/decisions/` — files the same module
declares frozen twenty lines above. The first session write-up to record "36 of the 80
workflow steps" would have made the check permanently red, fixable only by editing history.
Sites are now an explicit per-fact file list.

Two designs were built and rejected on measurement:

- **Strict equality over the whole registry** — the six-day replay above.
- **Dated invisible HTML-comment markers** (`<!--fact:active_rows 875 2026-08-27-->`) — killed
  by a measurement, not a preference: **6 of the ~20 drift sites are inside fenced code
  blocks**, where GitHub renders an HTML comment as *literal visible text*. The marker is not
  invisible at exactly the sites that drift hardest, and `ARCHITECTURE.md:37-38` are two
  consecutive rows of an 82-character box with no adjacent line to put it on. The staleness
  window is also the wrong axis: `ARCHITECTURE.md:114` is dated `(counted 2026-08-25)` and is
  exactly true today, so any `N ≤ 2` fires a false ERROR on the most reliable number here.

### 2. Two blind spots in `check_module_registry`, each hiding something today

- **An `operator` module a workflow RUNS.** `firmographics.yml` landed on 2026-08-26 running
  `research_firmographics`, `firmo_death_watch` and `company_type_analysis`; all three stayed
  filed as "a human runs this" while a cron ran them daily. The other three classes were
  checked in both directions and this one in neither.
- **`pipeline/*.py` was in no registry at all**, so `pipeline/roles.py` — the `roles` lane's
  whole subject and the artifact `ARCHITECTURE.md` §7c is about — was documented nowhere.

### 3. `HANDOFF.md`: the cap was respected and useless

245 lines against a 250-line cap, and **56,515 bytes**. Eighteen sessions had each written a
whole narrative as one line; the longest was 4,960 characters; **thirteen of the eighteen
already ended with `Record: docs/sessions/…`**, so the long version existed twice and the
HANDOFF copy was the duplicate. The file had been split from 753 lines on 2026-08-23 to fix
exactly this — so the failure is not that nobody tried, it is that the metric was gameable.

Eighteen entries moved to the records they already named, verbatim, each under a dated heading
carrying the sha256 of the line as it stood. Containment proof against `HEAD`: **0 of the moved
lines missing from the tree**. What stayed behind is assembled from spans of the same line, not
retyped.

```
245 lines / 56,515 bytes / 8,192 words / longest line 4,960
188 lines / 17,766 bytes / 2,658 words / longest line   365
```

The caps are now mutually reinforcing rather than mutually escapable: 250 lines, 3,200 words,
60 words per line, with fenced blocks, indented blocks and table rows exempt.

### 4. The morning checks, all fourteen, answered

Fourteen `Morning check <date>:` sentences were buried in prose and **not one had ever been
answered**. Answered from the committed artefacts, **8 of the 17 clauses failed** — including
two that had shipped to subscribers twice (`### Tel Aviv` and `### Jobgether` both appeared as
employer headings in the 2026-08-26 email against checks that said neither would).

An unanswered check is a **WARNING**, and the reasoning is pinned by a test so a future session
cannot "tighten" it without reading why: `discovery` writes the check on Tuesday and it comes
due while `jd-text` is pushing on Wednesday. An ERROR punishes the wrong agent, whose cheapest
route to green is **deleting the check** — the linter would then destroy the mechanism it
exists to protect. The *shape* of a row is an error, because that is the pushing session's own
work.

**Break-testing the check found a defect in the check.** `line.strip().strip("|")` swallows an
empty last cell, which is exactly what an unanswered check looks like: the row then failed the
length test and was silently dropped, so the one case the check exists for was the one case it
could not see.

### 5. `docs/backlog.py` and the index

3,457 lines, 314 items (340 by evening), 38 chronological sections, a lane's work scattered
across up to fifteen of them. The header said "numbers above 15 happen to be unique, by luck".
Measured: **28 numbers name more than one item.** `6` names five and is cited from
`audit-coverage.yml` and `daily-digest.yml`. It has already produced a wrong read inside the
file — a `- **244 — CLOSED.**` bullet is ambiguous between a closed `company-intel` item and an
**open, untouched** `ats-fetch` one.

Nothing renumbered (470 citations across 74 tracked files), nothing retyped. The index carries
**no line numbers**, deliberately: it is regenerated *into* the file it indexes, so a line
number is stale the moment it is written — which is how the first version reported its own
output as stale.

**The closed-item split is built, proves itself three ways, and was deliberately not run**
(filed as 291). A **safe** predicate — strikethrough AND a closure paragraph — matches 32 items
/ 363 lines, 10% of item text: not worth a bulk move. The predicate that would matter, a
closure marker in the first three lines, matches 95 items / 1,131 lines, 31% — and has
measurable false positives: `2@registry`, `7@infra` and `1@docs` all carry "CLOSED" near the
top and are open. Burying an open item is the worst failure available here. The real blocker is
upstream: **30 distinct spellings of "closed"** and no convention. The header now states one.

### 6. `docs/AUTOMATION.md` and `docs/RUN_LOG.md`

doc carries: **measured dispatch lag**. And a dictionary for the daily mail, which now carries
nine audit lines from seven lanes, with the column a dictionary is actually for — what it means
when a line is **absent**.

## Wave 2: the same treatment, turned on this session's own tooling

Two Opus attackers, an hour, twenty-five findings. Four of them are this repo's dominant bug
class — a check that is silently a no-op — aimed at the guard instead of the pipeline, and
one is worse than a no-op.

**The one that is worse.** `_fetcher_keys()` filtered `isinstance(k, ast.Constant)` and
silently returned a SHORT list for five of seven realistic dict forms: a `**` splat (which
yields the key `None`), a post-hoc `FETCHERS["x"] = f`, an `.update()`, a variable key, a
build loop. Silent is the bad half. The linter would then report the **docs** as wrong, and
an author doing exactly what it said would write a false number into four documents and get a
green build from both tools. Every non-literal form raises now, which is `facts/uncomputable`.

**The blind spot that was still blind.** The `operator`-a-workflow-runs arm — added the day
before, specifically to catch `firmographics.yml` — was a no-op for `python -m x`, `./x.py`
and `python -X faulthandler x.py`, and `python -m` is idiomatic here: `daily-digest.yml` uses
it twice. It also read a module name inside a `#` comment as proof, so a line saying "dropped
the nightly `python bd_employees.py` step" proved the opposite of what it said, and the fix it
suggested would have made `MODULES.md` claim a cron runs a module nothing runs.

**The guard that a comment could disable.** `_no_main_guard` tested for the *substring*
`__main__`. Adding a comment warning that `merge_research.py` has no guard — the canonical
import-runs-it module, named by that very sentence — dropped it out of the list, and
`MODULES.md` then listed seven modules while naming the eighth in the sentence beside them.

**The mechanism that could be silenced by a blank line.** One blank line inside the
morning-check table set `in_table = False` and dropped every row below it, and the check only
complained when *zero* rows survived: 20 of 21 predictions, silently, green. And
`_LOOSE_CHECK` scanned only the text *above* the table, so 147 of `HANDOFF.md`'s 189 lines —
every narrative section, which is where a session actually appends — were exempt from the
check written to stop a prediction being stated where nobody can answer it.

### `archive --apply` was deleted rather than repaired

Its three advertised proofs were all decorative. Both `open(..., "w")` calls ran **before**
the first assert, so a failed proof left two half-written files with no rollback. `TOMBSTONE`
never matched the link the writer emitted, so proof 2's filter removed nothing and key-set
equality held trivially. The body-hash list that the docstring *and* the generated archive
header both promised was computed and **never asserted** — 15 real mismatches. Proof 3 only
printed, and explained its difference away with a reason that was false: 14 blank separators
were dropped, not just the new tombstone lines.

A destructive command whose guard rail cannot fail is worse than no command. The design and
the measurement stay in item 291, along with what it needs before it comes back.

### The headline number was wrong by 63 items

`closed` demanded **both** a struck title and a closure paragraph, and 51 items announce an
unambiguous dated closure without striking anything — 22 of them `registry`'s. The old marker
also decided on *character count*: `**half closed 2026-08-25**` (5 letters before the word)
counted as closed and `**the restore half closed 2026-08-25**` (17) did not, so two items of
identical shape landed on opposite sides.

```
32 closed / 308 open   ->   95 closed / 244 open / 5 half
unassigned 39 -> 28     (LANE_IN_HEADING demanded backticks, so twelve items under
                         "From the registry lane" were filed as nobody's - and the index
                         was telling readers to burn down a list that was wrong)
```

**The lesson I would keep.** Every one of these was written this morning, by a session whose
entire subject was documents that are green and wrong. The linter cannot check itself, and
"I wrote it carefully" is the same claim the four documents it was written to correct were
making.
