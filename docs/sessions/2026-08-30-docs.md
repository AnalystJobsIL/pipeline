## The linter now enforces what it used to describe

`docs check` was `0 error(s), 12 warning(s)` and **exited 0**, so `CLAUDE.md`'s pre-push
contract passed with every prediction unanswered. It is `0 error(s), 0 warning(s)` on this
branch, and the rules below are errors rather than warnings.

**The morning-check grade.** Unanswered WARNs on the due date and the morning after, ERRORs
from the second day. `not yet due` may move its own deadline only in writing —
`until YYYY-MM-DD: <why>`, later than the due column, at most twice, warning past fourteen
days — and a re-date worded without a date is an error. A verdict must carry a digit or a
backtick: `INCONCLUSIVE - could not determine` passed the old shape rule while saying nothing
a reader can check. A verdict with an empty `answered` cell is refused.

**The guard that makes the escalation honest.** The old design was pinned by
`test_an_unanswered_morning_check_is_a_warning_and_never_an_error`, whose docstring gave two
reasons. The first — an error punishes whichever lane happens to be pushing — still holds, and
is why the grace exists. The second — "the cheapest way for that agent to go green would be to
DELETE the check" — is what `check_morning_rows_survive` removes: a row present at the
merge-base must still be in `HANDOFF.md` or, answered, in `docs/morning-checks.md`. Commenting
it out or moving it below the next heading counts as deletion, because the guard compares
**parsed rows**, not text. Archiving a row unanswered is refused too — but only for rows the
branch ADDS, so history stays untouchable and the asymmetry that file's own test pins is
unchanged. The superseded test was deleted rather than weakened: it pinned a premise that is
no longer true.

**The baseline is the merge-base, not `origin/master`.** The guard's own first run reported a
row `jd-text` pushed this morning as deleted here. A row added to master after this branch was
cut has never existed on the branch and cannot have been withdrawn by it; `origin/master`'s tip
would have made every open branch red the moment another lane pushed.

**`check_tree_is_current`** — the check for the half of the repo the linter could not see.
Measured, not asserted: run against the shared checkout it reports **151 commits behind, a
merge-base 71 hours old**, and ERRORs; run in this worktree — 6 behind, merge-base an hour old
— it warns. That discrimination is the whole design. Every lane's push touches `HANDOFF.md`, so
a rule keyed on "the certified docs differ" alone would be red for nine sessions each time a
tenth pushed, and a linter that cries wolf is one lanes learn to skip — this file's own header
says so. It never fetches: ten sessions run it at once and would contend on the ref lock.
`--tree --fetch` is the one path that does, and a guard asserts the no-argument path cannot
reach it.

**`check_unattended_proof`** — a branch that changes a workflow carrying a `schedule:` trigger
must add a morning-check row due today or later. Narrow on purpose: it is NOT extended to the
modules `docs/MODULES.md` classes `scheduled`, because `auto_expand.py` and its neighbours
change most days and a check that fires on every registry commit is one that lane would route
around within a week. Measured before shipping: of the 11 commits touching `.github/workflows/`
since the table existed, **4 added a row in the same commit and 7 did not** — one of the 7
being the 19:00 drain whose own entry says "the cron has not run".

**An escape hatch found by simulation, before it shipped.** The first draft also accepted a
HANDOFF line citing `run <id>`. This session answered three morning checks with run ids, any
one of which would have "proved" an unrelated workflow change. Removed: one row is the whole
contract, and a run that has already produced its number is still written as a row — due today,
answered today, the id in the verdict.

**A check that went green by checking nothing.** Bullet attribution resolves the section's
lane, and `LANE_IN_HEADING` requires the word "lane" after the name — which every closures
heading lacks. The first version therefore resolved None for every bullet in the file and
attributed **nothing at all**; the count fell to zero for the wrong reason, and it looked like
success. `bullet_lane()` reads any backticked known lane out of a heading instead. Proof it
still checks: against the pre-session file it flags exactly the **12** real originals and
**none** of the 8 collisions; against this branch, 0, because the work is done.

## The definition of done, and rule 5

The clause is in three places — `docs/AGENT_BRIEF.md`'s "Definition of done" (the operative
version), `CLAUDE.md`'s pre-push contract (item 3, the two-minute version), and
`ARCHITECTURE.md` §0, which is where it belongs because **both deliverables are produced by a
run nobody watches**. Four parts: the proof is an unattended run (`event: schedule`, and a
`headSha` that contains your commit — dispatching it yourself is not that); HANDOFF quotes the
exact counter, not a nearby number that shares a word (`JDs fetched inline: 132` is the inline
enricher, not the nightly backfill); until then the entry says "unattended run not yet read"
and a morning-check row carries the date it comes due; a step that can produce zero makes zero
visible where a human reads daily.

Rule 5 quoted "5,000 requests/month, ~6,798 already used, permanent and unrecoverable" — a
prohibition with moral weight, and wrong for two days: `pipeline/bd_budget.py` says **unlimited
through 2026-08-31, 5,000/month from 2026-09-01**, and pins both sides of the boundary so the
rule changes itself on the day. It now cites the command and never the number, and names two
modes a session must declare. **Dry** — no `secrets.env`, `JD_BD=0 BD_RUN_CAP=0` — is where the
ban's own failure mode lives: a disarmed rung does not error, it returns a refusal, and one
such pass wrote 57 of 57 rows dead. The rule now says a zero from a dry worktree is not
evidence, and no `dead` / `parked` / `zero-confirm` verdict may be written from one.

**Why the copy ban stays.** Its stated rationale — an exhausted pool — expires on 2026-09-01.
The real one does not: a copied `secrets.env` is an uncapped spender (`BD_RUN_CAP` unset means
no cap, `PAGE_UNLOCK_BUDGET` is 100 per process, `JD_BD` defaults to 1) in a tree nobody is
watching, and from 09-01 ten concurrent sessions at that rate is the month's pool in five days.
What changed is that the rule names the trap on the other side too, and `437@infra` asks for
the third option — one loader honouring a path, so a rung can be armed without copying.
