## 1. `Oak` — the name was the veto, not the parking (`522`)

The row had been parked since 08-28 and the fold was refused anyway. `roles._alias_fold_target`
refuses first on `name in registry_names`, and `run.py` builds that set with
`load_companies(active_only=False)` — so **any** row wearing a string that `ALIASES` declares
cancels the declaration, silently: no log line, no counter, no ledger field. Parking harder was
never going to work.

The board answered the identity question. `operagroup.teamtailor.com/jobs` titles itself
*Current job openings - Opera*; its filter values are the brands `Opera / Accuro / HFL /
Meritus / Oak`; the `Oak` cards read `Oak Isle of Man`, `Oak Guernsey`, `Oak Bahamas`, Trust and
Corporate / Client Accounting, for a `company_id` the page names **Oak Group**. **0 Israel
cards, 0 `Product Analyst`** — the Indeed posting was never this board's.

So the row was renamed to the employer its own board names, `Oak Group (Isle of Man)`, and
retired `redundant`. Measured after: `_alias_fold_target("Oak", …)` → `("Oak - Identity
Security OS", "declared")`, and `None` again the moment a row named `Oak` is put back.

Two traps, both recorded in `ARCHITECTURE.md` §2:

* **`Oak Group` was refused as the new name.** `identity_key` strips a trailing `group`, so it
  reduces to `oak` → `ALIASES` → `oak identity security os`: the obvious name would have folded
  this **foreign** row onto the Israeli company's identity. Check the key, never the string.
* **A rename reads as a vanished row to `census_diff`.** The reason went into the census's own
  stored note (`removed 2026-09-01: renamed to …`) rather than deleting the key, so the row's
  disappearance is *explained* and the alarm still fires for anything else.

Cost, stated because it is a real one: the 220-char cell was saturated by a PROTECTED
`dark-triage` segment, so the first (113-char) attempt was **dropped whole and silently** by
`notes.append` — the exact "a row that can never be retired" failure §2 documents. The segment
was cut to 98 chars, which fit, and it evicted `listing-hunt 2026-08-29: another company's
board`. The terminal verdict says that more precisely and permanently.
