### 3. Three activation branches overwrote the whole notes cell

`audit_empty_rows:283`, `crack_walled:254`, `deep_validate:327` each did `fr[5] = "..."`
while flipping the row to active. That is the one moment you can least afford it: the
assignment deletes the terminal token that keeps the row out of the wrong pool and the
`dark-triage` mode that routed it there. All three now call `notes.replace_own`.

`test_every_note_writer_uses_the_append_log_helper` could not catch these — it looks for a
hand-rolled *trim*, and a whole-cell assignment does no trim. The new guard walks the AST
for `fr[5] = <not a call>`.

## The two critical ones were in my own fixes

### C1 — the crack gate was a 24-hour delay, not a gate

`_page_names_company` correctly refused to activate Bancor onto The Bancorp Bank's board.
It returned `novrfy` to do it — and that branch does `fr[3] = got[1]`: it wrote the
**proven-foreign URL in as the row's address** and stamped `crack-walled …: host documented`.
`host documented` is a `probe_candidates` pool token *and* `listing_hunt`'s documented
fast-path token. So:

```
19:00 Mon  crack_walled  documents Bancor -> careers-bancorpbank.icims.com
05:00 Tue  probe_candidates polls The Bancorp Bank's page daily
19:00 Tue  listing_hunt fast-path scrapes the stored URL:
             il and not is_foreign(name, seed)  ->  is_foreign is False on an ATS host
             looks_like_a_job_listing_page      ->  True
           fr[4] = "true"
```

Same wrong outcome, one day later, attributed to `listing-hunt` instead of `crack-walled`.
The reviewer scoped it exactly: the other two blocked candidates (`Fintica`,
`Phoenix Financial`) *would* be caught by `is_foreign`, so the only population that leaks is
walled-ATS subdomain tenants — precisely the case the gate exists for, and the whole 25-row
crack pool. `listing_hunt` already refuses to persist a foreign URL, with a comment saying
why; the crack path now has a `notours` verdict that writes the note and never `fr[3]`.

### The gate was also far too strict to keep

Measured against ground truth — 60 rows the pipeline has already verified as that company's
own board — the first version returned False on **12**: Meta, Akamai, Ford, Microsoft
(Xbox), Microsoft Israel, Synopsys Israel, Sepio, Finaloop, Volkswagen (CARIAD), Greeneye,
Supersonic Studios, Estee Lauder. Three causes, each already a paid-for lesson in this repo:

1. a plain 403 to a urllib fetch (`Bit`'s own careers page) — the crack loop reached these
   with Playwright, so re-fetching with urllib is *weaker* evidence than what produced the
   candidate;
2. **strict TLS** — `scan_dead_domains.alive()` uses a lenient context on purpose, because
   "strict TLS on the scanning machine produced 6 false positives" (section 2). I
   re-introduced it;
3. `strict=True` wants the name's words consecutively, and **46 registry rows are named
   `... Israel`**.

Now: lenient TLS, unlocker whenever a key exists (not only behind `SCRAPE_VIA_UNLOCKER`,
which `audit-coverage.yml` does not set), a suffix-stripped retry, three-valued so an
unreadable page is *no evidence* rather than disconfirmation, and `continue` so one foreign
capture no longer abandons the company.
