## 4. `599`: one detector for tests the calendar turns red

`tests/calendar_rot.py` scans every `tests/test_*.py` AST for both shapes, scoped to the windowed
predicates that judge a date (2,493 of the suite's 2,498 date literals are post-2021, so no
file-wide rule can work):

* **(i)** a literal date VALUE on or after `today − window`, in a test calling a predicate that
  reads the wall clock, with no frozen clock handed in;
* **(ii)** a frozen literal `today` handed to such a predicate in a test that also builds a
  fixture from the live clock.

A literal already older than its window, a frozen pair, a live pair, a docstring, or a date
inside a longer string are not findings. Rule (i) counts future dates too, so a finding can only
disappear as the calendar moves: the guard cannot rot.

**Seeded, then measured on the tree.** Each instance's text at the commit before its fix is a
fixture (short file names: the 90-character originals broke a worktree checkout under Windows'
`MAX_PATH`, found by this session's own scratch checkout). **5 of 5 found on the day each was
written, 0 in the fixed texts, 0 on the tree — no allowlist.** The first tree run found 2, both
mine: `board_freshness` and `read_ledger` read no clock at all, and came off the list. The sixth
instance (`archive_evidence`) had no shape in the test — the function mixed clocks — and no
scan of a test can see it; it is documented, not seeded. The 09-11 JSON-key scan inside
`test_the_freshness_window_is_one_constant_and_no_fixture_sits_inside_it` is folded in.
`queue_state.tried_within`/`row_due` take `today`, the seam 8e9af0c's fix lacked. **What it cannot
see:** a dated fixture reaching a windowed predicate through a caller (`main()` of a tool), which
needs a clock-shifted run of the suite, not a scan.
