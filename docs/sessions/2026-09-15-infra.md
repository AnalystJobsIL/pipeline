## 3. What shipped (`archive_evidence.py`, one commit; tests and docs in the next)

- **Two families.** `ARCHIVE_SIDE = {net, server, throttled}`, `HOST_REFUSAL = {http,
  blocked, excluded, limit-url}`. `_Pool.record` parks a host only on a refusal; an
  archive-side result feeds a pool-wide streak instead. A timeout (`pending`) neither counts
  nor resets — see §2 for the three nights that decided that.
- **One pause primitive.** `_throttled` became `_pause(sent, wait, reason)`: the same
  lock-and-`next_send` push, one `episodes` counter for a 429 (its own Retry-After every
  time, else 300 s) and for an outage streak (`OUTAGE_AFTER` 8 requests, `OUTAGE_WAIT_S`
  90 s); the third trigger of either kind sets `stop`. The streak counts REQUESTS (the
  in-thread 15-s retry included) and skips the per-URL retry when it opens the pause; a
  result whose send predates the current pause's end is not evidence about the archive
  after it. `slot()` now refuses a wait that ends past the budget (it slept through it and
  sent). The `self.throttle_at is None` guard that blocked a second Retry-After is gone,
  and `caps.throttle_wait_s` is no longer mutated.
- **`interleave(postings, boards)`**: a board after every `postings // boards` postings,
  one in six at the production caps.
- **`read_ledger` → `refusals`** beside `attempts`; `cooldown_days(err, refusals,
  attempts)` is tired at four refusals or twelve attempts of any kind (`unverified` is a
  refusal: 149 of 206 were LinkedIn/Indeed/Comeet, the hosts that block the archive's
  crawler).
- **`net:URLError:<reason class>`** in the ledger; production lines carry their own clock.
- **The stamp**: `captured` (named or `cached`), `net`, `server`, `refused`, `stop` (only
  when set); the alarm is `zero-produce: 0 named of N planned (accepted M, net a, server b,
  refused c[, stopped X])` — the token the mail check greps, on the night that names
  nothing rather than the night that accepts nothing.
- **Tests**: seven new `test_wayback_*` with exact counts (a 24-request archive-down day,
  `[8, 16]` as the requests at each pause, `waits == [120.0, 60.0]`), the ledger fixtures
  dated relative to the run's own `today`; the one-episode throttle test rewritten as the
  two-episode one; seven records in `tests/mutations.json`. `tests/conftest.py`:
  `web.archive.org` / `archive.org` in `FREE_BUT_LIVE_HOSTS`, and the same ban on
  `http.client.HTTPConnection.connect` because `archive_evidence._OPENER` never passes
  `urlopen` — asserted from inside a test the code change can kill (a conftest-only test
  reads CANNOT-FAIL in `guard_kill`, which keeps `tests/` at HEAD).

## 4. What the design review found before it shipped (one Plan agent over the file)

Folded: `slot()` sleeps outside the lock, so a `next_send` push cannot stop a thread already
asleep (≤ 2 sends leak per pause; they are excluded from the post-pause streak by send
time); `slot()` checked the budget before its sleep and never after; the second episode
could never take its own Retry-After through the `throttle_at is None` guard; the two
hand-built state dicts in existing tests would have KeyError'd on `refusals`; the pending
lines are all timeouts (§2), so the streak and the alarm had to be defined against them.

## 6. Clause 4

**Deleted or unified.** `_throttled` (one code path for two reasons); the `throttle_at is
None` guard; the mutation of `caps.throttle_wait_s`; the run-wide `now` for production
lines; the `submitted == 0` alarm rule.

**Extended rather than duplicated.** `_Pool._throttled`'s lock-and-`next_send` push is the
pause for both triggers; `Report.counters()` is still the one path to the stamp;
`cooldown_days` grew a parameter instead of a sibling; `conftest._no_paid_calls`'s check
became `_refuse_if_banned` and is called from two hooks; the existing throttle and park
tests were rewritten, not duplicated.

**Rejected, on the number.** A proxy egress for `/save/` (on 09-15 the availability API
answered 40/40 from the same runner IP while every `/save/` failed — the egress is not the
variable; 0 credits either way). A second archive (0 lines of reader code for one; no
anonymous API at archive.today). Raising `WAYBACK_REQ_CAP` / `DAY_CAP` (50–138 of 220 on
the last three nights). Treating a timeout as archive-side for the streak (it would have
paused 09-05, 09-07 and 09-09, which named 7, 13 and 4). A per-URL second retry (the
pool-wide streak covers the same outage in 8 requests instead of 15-s waits per URL). A
pre-run health probe of the archive (the availability endpoint was up on 09-15 while
`/save/` was down). New env knobs for the three constants (the 09-04 record already lists
"seven env vars on one step" as a cost).

**Made harder for the next lane.** Three module constants that a test pins by exact count
(`OUTAGE_AFTER`, `OUTAGE_WAIT_S`, `PAUSE_EPISODES`); a `refusals` key every hand-built
ledger state must carry; a ban on `archive.org` below `urlopen` that any test reaching the
archive through any stdlib opener now trips as a `BaseException`.
