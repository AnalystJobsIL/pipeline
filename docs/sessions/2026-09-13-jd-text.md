## 587: why the TEXT carries the closure, not the job dict

The brief's shape was "stamp before the sentence is removed". At the `_reclean` door that was
already true. At the fetch door there was nothing to stamp: `extract_jd` removes the header,
sentence included, and hands back a clean posting.

Setting `job["jd_why"]` in `maybe_fill` looks like the obvious fix and reaches nobody. `_alive`,
`board_jobs` and `_record_run` read sqlite rows, and `upsert_matched` writes `MATCHED_COLS`, which
has no `jd_why`. Writing it there is `roles`' file and a column migration.

So the capture keeps the page's own sentence as its first line, the last step of `extract_jd`
(after `_HEAD_SKIP`, or the intro trim takes it too — a mutation record pins the order). Measured
on the kept shape: `jd_body`, `strip_head`, `furniture_at` (None), `_HEAD_SKIP`,
`mid_sentence_head` (False), `reclean_text` (None) and `better_description` all leave it alone.
`roles.page_says_closed` fires on it the same morning, `roles` writes its url-bound memory, and
`save()` / `_stamp_closed_pages` write the stamp. No change in `roles.py`.

**The one exposure**: a row on a LinkedIn url with the sentence but a board source is not closed
by `page_closed`'s all-discovery gate, and would publish the line as its first line. Measured
over `matched`: one row carries the sentence (`mizrahi tefahot bank|analyst`), and it is
LinkedIn-only and closed.

## What is harder for the next lane

* `extract_jd` can now return a text whose first line is page chrome, on purpose. A new cutter
  must leave `with_closed_line`'s line alone; `test_the_kept_closing_line_is_invisible_to_every_cutter`
  goes red if it does not.
* A job dict can carry `_jd_why`, and `fetch_scrape` hands out the cached card objects
  themselves, so the key sits on those cards in memory for the run. Nothing in the digest writes
  a cache today (`run.py` writes neither) and `upsert_matched` ignores unknown keys. A future
  step that dumps job dicts or the in-memory cache wholesale would publish it.
* The fixed point now has THREE stores (sqlite, the ledger, and the card that is upserted every
  morning), and a text repair is not finished until the card agrees too.
