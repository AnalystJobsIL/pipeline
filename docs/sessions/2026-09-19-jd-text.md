## What changed

**Commit 1 `44ac381` — `jdfill`: a page's own `<base href>`, and a site label is not a posting id.**

* `_page_links` resolves relative hrefs against `<base href>` when the page declares one, first
  64 KB, same-origin only (a foreign base would resolve every posting link off the employer's
  own board, and same-origin is the whole trust model of that function). Live before/after on
  Google: `role_addresses_on` returned
  `…/applications/jobs/results/jobs/results/120188596949787334-research-data-scientist-ii-waze`
  (**GET 404**); it now returns `…/applications/jobs/results/120188…` (**GET 200, 1,137,259
  bytes, `extract_jd` 3,761 characters, 4 marker families, `looks_like_jd` True**). The link
  list is **28 addresses before and after** — the fix changes which address, not how many.
  Oracle CE declares a root-relative base (`/hcmUI/CandidateExperience/he/sites/CX_3001`) and
  links by absolute path: **6 links before, 6 after, 0 role addresses either way**.
* `is_job_url`: `_SITE_LABEL` (`^[A-Za-z]{1,3}_\d{1,8}$`) is excluded from the 2+-digit
  override. Census over the **2,548** distinct urls in `scraped_cache.json` +
  `cloud_state/seen.db` (`scratchpad/census_is_job_url.py`): **8** end in a `_LIST_SEGMENT`
  word and pass on an earlier 2+-digit segment, and this flips **exactly 1** —
  `ehsb.fa.em2.oraclecloud.com/…/CX_3001/requisitions`. The 7 Siemens `/<32-hex>/job/`
  postings, which are the reason the override exists, keep their admission;
  `…/CX_3001/job/5108` is still a posting.
* `comeet=` joins the posting-id query keys, so `…/careers/comeet/?comeet=D7.C29` — the one
  address a widget board can give a single position — is no longer refused before a byte.
