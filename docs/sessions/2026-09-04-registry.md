## 2. Why auto-expand could write it, and the two closes

— exact, lower-cased on both sides since the Comeet miss of 2026-08-27. A token is one
writer's SPELLING of a board: `resolve_deep._detect_ats` writes the Workday composite
`tenant/site`, and `resolve_llm` returns whatever the model read off the evidence — the
site alone, today. One board, two spellings, both lookups green, and the row appended with
`check_invariants` exit 0; only the suite's `test_no_two_active_rows_share_a_board` saw it,
at test time, as the one red in `guard`.

Closed at both ends, small:

* `_boards_now` also emits the ADDRESS — `_url_key`, `("url", netloc, path)` with the same
  lower/strip-slash normalisation as `check_invariants.shared_boards`, so the gate and the
  guard agree — and `_board_taken(plat, tok, api, boards)` checks both keys at the two sites
  that decide (`_probe_resolve`'s `probe-dup-board` refusal and the append in `main`).
* `resolve_llm._workday_token` derives the composite from the api url, so the writer that
  produced the odd spelling now spells it the registry's way.

`test_the_board_guard_sees_one_address_under_two_token_spellings` holds both: the token key
alone is asserted blind (that is the production miss), the url key catches it case- and
slash-blind, a different tenant is a different board, and the empty address is not one.
