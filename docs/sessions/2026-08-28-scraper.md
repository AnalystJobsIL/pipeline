## What changed

**1. `uncached` / `unvisited` on the `collect` stamp, with an expansion-adjusted ratchet.**
`uncached` is active scrape rows this run leaves with no cache key; `unvisited` the part with
no rot entry either — 0 by construction on a complete night, so any N is an event, and it is
the leading indicator of the 287 a night before they are 287. Measured against **the cache and
the rot file that exit actually leaves on disk**, so an abort night cannot describe a file that
was never written.

The level is never an alarm — 196 of the 216 were `empty`, which §5a calls a measurement, and
any ratio bar under ~50 % lights the mail's bold `Stages:` line every morning and buries the
tokens that line exists to carry. The event is
`(uncached − uncached_base) − max(0, rows − rows_base) ≥ max(25, 5 % of rows)`.

**2. A sixth ladder rung: the embedded-board handoff.** Some of the 196 are a marketing skin
over a board this repo already fetches. `_render` now captures the page's own request URLs and
`window.comeetvar` (Comeet writes uid+token into `window`, never the markup — which is why an
unrendered probe of Nova's page finds the word `comeet` and no board); registry's own detectors
name the platform and tenant; the identity gate judges it; and the verdict is recorded on that
row's rot entry whether or not anything is fetched. Placed after the ladder's own
`if add.israeli: return done()`, so it is *structurally* unable to change a row the five
strategies already read.

**3. All 287 rows scraped locally, 0 Bright Data credits.** `--only-missing --apply` in a
worktree, 10 workers, 15 minutes.

## The adversarial waves

Three read-only Opus agents against a bundle in the scratchpad with **no `.git` in it or above
it**, so the `git checkout --` that destroyed another lane's uncommitted work yesterday exits
128 there. They killed three of this change's claims, and every fix is in this session's
commits.

- **The handoff would have published another company's jobs under our name.**
  `embedded_board_ok`'s near-equality composes two vocabulary strippers into
  prefix-containment, so it admits `<our name> + <any vocabulary tail>`. Six LIVE registry rows
  were driven end to end — `Nova` ← `novalabs`, `Zoomd` ← `zoom`, `Skai` ← `kai`, `HUB Security`
  ← `hubinternational`, `Aqua Security` ← `aquatech`, `one …` ← `onemedical` — and **492 of 496
  active scrape rows admit some slug strictly longer than their own core**. `_embed_admits` now
  also requires a declared tenant or an EXACT normalised name match: it refuses all ten
  demonstrated leaks and keeps all five boards the gate legitimately admitted. **The cache is
  clean** — `embeds_won=0` and no posting carries `_board`, so the leak never reached the
  artefact. Filed for registry as `348`.
- **`unvisited ≤ uncached ≤ rows` was false.** The abort exits return before
  `write_json(ROT_PATH, rot)`, so the count read a dict that will never be a file: on a
  shrink-abort night a row scraped *successfully* read as never-visited and raised a false
  `unvisited-N`; on a mass-failure night a genuinely never-seen row read as visited. Fixed with
  `rot_written`, the same discipline `written` already applied to the cache.
- **The alarm fired on benign growth and slept through a real leak.** A one-night delta was
  wrong three ways, measured over the real series: the bar was calibrated on the quietest pair
  (Δ3) while the deltas are +10/+29/+29/+4; the whole 216→287 jump *is* the pool moving
  421→496; and a 24-a-night leak is silent forever — 168 rows, a third of the pool, in seven
  quiet nights. Hence the ratchet.
- Also: `--only ""` (an unset shell variable) parsed to the empty set, which is falsy, so a
  flag typed to NARROW ran UNSCOPED — rewriting the cache, parking rows and stamping. One
  scalar in `scrape_rot.json` killed the night after all the Chromium work. `_alarm`'s `rows=`
  argument was shadowed twelve lines in. Two shipped assertions were vacuous. All fixed.
- One claim they raised was **false and worth recording**: `discovery_daily.py` does not stamp
  `collect`. `refresh_scrape_cache.py` is the only stamper.
