## Rejected alternatives (from the design critique, before writing code)

- **Reading the ledger's `tags` snapshot for rendering** — it stores only
  skills/family/track/years/degree/ai; the board needs the section extractors anyway for
  tasks/soft/ai_req, so it saves one `roleprofile.extract` and creates two vocabularies (the
  archive would render last month's beside today's board). A record, not a cache.
- **Adopting `seniority._REQ_HEADER`'s lookbehinds** — `(?<!the )` kills "The Requirements:"
  and `(?![,.;])` kills "Requirements." — the footer is rejected in the candidate loop instead.
- **Mutating `stats` from a renderer** to carry the render line — the payload's `summary`
  is an infra contract read by tests; `render_issues=` is a kwarg and `summary["render"]` is
  set by run.py, deliberately.
- **Unifying the three audit blocks** — `tests/fixtures/company_intel/mutations.json` pins
  the source text of two of those lines; deferred behind BACKLOG 142 (retire `build_digest`).
- **Dropping a blurb that names another employer** — acquirers and customers are named
  legitimately; counted instead.
- **`roles.tenant_slug` for the shared-board check** — it is the second URL segment, which
  for a Greenhouse job url is the posting id; the first real-data run grouped eight unrelated
  companies under the LinkedIn host. `rolecard._tenant` (BACKLOG 143).

## Defects the rehearsal found before any reviewer saw it

1. The first split used line numbers from a read taken before the roles lane's hunks landed
   in `digest.py`; the rebuild put `_firmo_facts` in the wrong file and cut the board
   docstring. Anchor-based slicing; the golden caught it (`SyntaxError`, then 6/6).
2. `_md_blurb` stripped parentheses from prose ("(like scaffolding, …)"); only `` ` [ ] < > * _ ``
   can break the mail. The golden's line-14 diff showed it.
3. `Tel Aviv District, Israel` rendered "Tel Aviv" because the glued-city substring search
   ran before the region check; a district-only address now reads "Tel Aviv area".
4. The EEO guard first looked 160 characters ahead and rejected a real header whose *section
   ended* with the footer; it now looks at the first fragment only.
5. Hyphenated place tokens (`tel-aviv`, `ramat-gan`, `תל-אביב`) were not indexed — the
   totality test over `israel.py` caught nine.
6. The email alarm line was `_md_esc`-ed into `role\(s\)`; alarms get `_md_alarm` instead.
7. `_bullets` dropped any requirement under 8 characters — a bare "Python" or "Excel" bullet
   was junk. The first fix (keep it when it contains a signal word) measured badly on the
   store: split leftovers "At least", "Fluent", "Strong" came back and displaced real bullets
   from the 12-cap (a soft-skill chip vanished). Final rule: a short fragment survives only
   when it IS a lexicon skill name (`_is_skill_name`).
8. `_looks_like_header` called any two-word fragment starting with a capital a header, so
   "Team player" never reached the soft-skill classifier; the first relaxation let "At least"
   / "You have" / "Product analytics" through. Final rule: a two-word fragment that is a
   skill or matches a soft-skill regex is a bullet; everything else keeps the old rule. The
   card-dump diff against the step-5 dump is now exactly: 3 hyphenated locations relabelled
   (`Tel-Aviv`, `Petah-Tikva`) and one card gaining "Team player" (+ its chip) —
   `tests/rehearse_render.py --cards --cards-golden <step-5 dump>` → `5 cards differ`.
