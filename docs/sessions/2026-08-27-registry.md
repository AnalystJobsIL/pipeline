### The own-site rung — the larger lever

`_site_from_guess` asks the inverse of the question `_site_from_slug` asks. That one asks
LinkedIn for `about_website` and got **0 of 3** (BACKLOG 178), which is why it is off. This
one asks the *site*: LinkedIn says the handle is S — does the page at `S.<tld>` link **back**
to `linkedin.com/company/S`? A two-way binding neither side can fake alone, at no LinkedIn
budget. Over the 364 names with a valid handle: 119 domains answered, 104 named the company,
53 carried the linkback, **49 passed all three**.

The linkback is not fussiness. The looser rule admits `agoda.com` and `iai.co.il`, and a
wrong own-domain page is worse than none — it is exactly what
`resolve_llm._own_page_names_token` reads, so it would corrupt the one check the paid tier
has. Evidence that can corrupt a verifier is held to the higher bar. It costs ~4 of 11
probable true positives; relaxing it later is a measurement, not a guess.

## Two things I got wrong, corrected in place

1. **I told the operator to call `activation_verdict(..., token=slug)` rather than
   `activation_ok`, because the latter drops the token.** It does drop it — and dropping it is
   *better*. Measured: `Ashley Digital` is **refused** by `activation_ok` (the URL-derived
   token makes `board_vouches` return None, which forces a page read, which returns False)
   and **admitted** by `activation_verdict(..., token="ashley")`, because a supplied token
   makes `board_vouches` True and short-circuits before any page is read. Handing the gate a
   token we synthesised from the name is handing it its own answer. The rung uses
   `_row_for_ats`'s existing, mutation-covered `activation_ok` call site, unchanged — which
   also means `GATE_CALLERS` needs no edit.
2. **I claimed the rung would spend zero Bright Data credits.** It would have.
   `identity_gate.page_names_company` reaches `bd_rescue.unlock` when the page it holds is
   under 2,000 chars, `PAGE_UNLOCK_BUDGET` is 100 per process, and `auto-expand.yml` sets the
   key. The rung is free only because it is *made* free: it fetches the page itself and only
   consults the gate at ≥ 2,000 chars. Guarded by
   `test_the_own_site_rung_demands_a_linkback_and_cannot_spend_a_credit`.

I also predicted the drain would oscillate — prune a registered name, `known` loses it,
`added` puts it back. **It cannot**: the card loop already skips `c.lower() in have` 80 lines
earlier. The guard stayed, with a comment that says it is redundant rather than claiming a
fix.
