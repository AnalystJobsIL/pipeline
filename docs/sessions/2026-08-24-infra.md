## What was wrong (each one verified before anything was written)

1. **Hand-overs lost data on every conflict night.** Nine workflows carried their own copy
   of a commit/pull-rebase/conflict block; on a conflict each did `git reset --hard origin`
   and copied its CHECKOUT-ERA files back. Only `companies.csv` and `scraped_cache.json`
   were merged. Proof: `82d425c` (listing-hunt 22:12) stamped `repair`; `0b41823`
   (expand-bot "row-merged state", 23:40) restored auto-expand's 20:00 copy of
   `pipeline_stages.json` and deleted the key; same on 08-23 (`33d0306` → `bab228f`). The
   2026-08-25 mail read `repair: never run`.
2. **A crashed digest sent no email.** The relay dedups on the sha256 of `digests/latest.md`;
   a crash left yesterday's file → same hash → silence, and only a red run nobody polls.
3. **The mail arrived on the 08:30 relay.** The 05:00 cron queued 36 min and ran 32 (run
   32813499709, 05:36→06:08); the 05:45 relay (run 32815273635, 06:02) printed `already
   posted … 08-24`. Inbox issues 05:59 / 08:59 / 06:23 on three days.
4. **8 of 15 digest steps were `continue-on-error` AND `|| echo "… skipped"`** — a crash
   read exactly like a step that ran with zero work; `Mark digested roles as sent` swallowed
   a real crash the same way; no step was `if: always()`, so a timeout (budgets summed to
   ~170 of 150 min) discarded the run including the paid LLM verdicts.
5. Only `collect`/`enrich` reached the bold `Stages:` line (BACKLOG 114); the `[health]
   skipped` except dropped every `Boards` line and `stale.json` silently; `main()` had no
   crash handler; no `::group::`, no `$GITHUB_STEP_SUMMARY` anywhere; the tail claimed
   `docs/index.html` on scoped runs (BACKLOG 115).
6. `merge_json_cache.merge` could not express a deletion (BACKLOG 95) and turned a corrupt
   side into `{}`; `merge_csv_rows._TOOL` lacked `url-repaired` (12 live segments) and
   `self-heal` (4); `_merge_notes` resurrected segments a probe wake had deleted (15/60).
7. The shared worktree was mid-failure: local `master` two commits behind origin with a
   stale staged copy of the render lane's work, a staged `BACKLOG.md` blob that would have

## Adversarial wave 1 (3 Opus attackers) — 6 HIGH, all fixed and pinned

- **A delivered digest could be replaced by a "No digest" notice** (persist pushed the mail,
  then exited 1 over one refused file; or a red gate with persist `if: always()`) — and the
  notice then lied ("nothing was marked sent"). Now delivery decides: origin's `latest.md`
  headed with today's date is never touched; the notice says when roles WERE marked sent.
- **A same-day re-run** (fresh runner, no `out/`) hit the same hole — the date-in-heading
  rule covers it.
- **Notice injection**: an exception message carries scraped bytes; the notice is the one
  markdown built outside `digest.py`. Escaped (`` \ ` [ ] @ `` and `<tag`), newlines
  folded, the run URL must be `https://…`, a traceback line cannot close the fence.
- **An untracked owned file that failed its gate was unlinked, then named in `git add`** —
  fatal pathspec, the whole run lost (the very lesson in the docstring). Staged paths are
  filtered.
- **`--own cloud_state` on a vanished directory pushed an empty tree and reported
  success.** Vanished tracked files under an owned directory are restored, never deleted.
- **A hot sqlite journal made `quick_check` fail read-only** → `seen.db` reverted to the
  checkout copy; and journals / `.tmp` files were being staged. Read-write open; side files
  skipped.
- **A skipped pipeline** (hard-failed CLI install) with persist green produced no notice:
  yesterday's digest re-relayed unlabelled. `cli` is `continue-on-error`; a red job whose
  pipeline never ran warrants a notice.
- MED: the second conflict in one run was judged against the checkout base (origin's later
  edits looked like ours) → base moves to the merged commit; the deletion rule needed a floor
  (a run that dropped >25 % of a cache is a broken run: kept, warned); `_last_run_alarms`
  could raise on a malformed file and alarmed the same failure three mornings (now 0–1 day,
  never raises); self-heal's Monday `stale.json` was unowned (owned, per-company);
  `git config` mutated the checkout's identity (now `-c` per commit); the `pipeline` step
  timeout (75) sat below its own budgets (110; job 285); eight workflow comments still
  described the old gate behaviour; the board publish's `git add archive.html` was the
  unfiltered pattern; `Stage stamps` steps are tolerated. Measured, not changed: `_TOOL`
  widening collapses 0 of 1,229 registry rows; `discovered_cache.json` holds 1 duplicate key.
- Refuted by the attackers (kept as is): shallow-clone git operations, `toJSON(steps)` in
  `env`, step ids vs `CRITICAL_STEPS`, the relay hash never colliding across days, the new
  stage alarms not firing spuriously (`repair never ran` is true), every `--own` list
  matching what the scripts write (two exceptions above, both fixed), `[skip ci]` on every
  commit, the cron table.

## Adversarial wave 2 (2 Opus confirmers) — every wave-1 fix confirmed; 3 HIGH new, fixed and pinned

- **The runner has no git identity** (`actions/checkout` sets none; `x@host.(none)` is refused),
  so `git pull --rebase` failed on every divergence: the commit path misread it as a conflict
  every night another workflow had pushed first, and the outcome step — which has no
  fallback — could not push the failure notice on exactly the nights it exists for. The
  suite missed it because the fixture clones have no identity either. Now the bot identity is
  process env (`GIT_AUTHOR_*` / `GIT_COMMITTER_*`), never `.git/config`; pinned with a
  fixture that strips every `GIT_*` variable and HOME.
- **A vanished explicitly-owned file was pushed as a deletion, ungated** (fix #2 covered
  directories only; `run_gates` skips absent paths). Restored from HEAD like the directory case.
- **The re-gate route fed the rebased tree back as "ours"** (after `checkout HEAD -- bad`,
  `rev-parse HEAD` was the corrupt merge), so a clean rebase that failed a gate lost the run's
  bytes. `ours_rev` is the run's own commit; the gate failure counts toward the exit code.
- MED: a red persist (one refused file, the rest pushed) skipped the board publish for a day
  with no notice (delivery decided correctly) — publish now runs whenever the pipeline
  succeeded and the job was not cancelled. LOW: an ignored owned path made `git add` fatal
  (`-f`); `delivered` keys on the lstripped heading like the gate; a green run that wrote no
  digest file (a dispatch straddling UTC midnight) fails the pipeline step loudly instead of
  a silent day; a backtick inside an escaped code span is swapped for U+02CB; the run-page
  summary writer never raises.
- Refuted (kept): the `is_dir` heuristic, the vanished-file restore vs the conflict path, the
  autostash vs `rewritten` diff, the exit-code contract with `daily-digest.yml`, the hot
  journal replay, the mass-deletion boundary (5/20 allowed, 6/20 kept), the re-attack on
  `notice_warranted`'s outcome table (17 combinations), every injection vector into the
  notice (`steps` reaches it as keys + outcome only; every stamp value is integer-derived).
  One by-design corner left: on a day the render lane ships its stub email, a red gate is
  tomorrow's line, not a notice — the stub IS a delivered mail.
