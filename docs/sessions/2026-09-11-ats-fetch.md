## 0. What was wrong, and the part nobody could have guessed

The verdict this lane's number has been waiting for **was written on 2026-08-30, tested, and
never committed.** It sat as a dirty working tree in `.claude/worktrees/atsfetch-0830` —
`BoardAbandoned`, `health.abandoned`, `_hosted_board_alive`, `fetch_recruitee`'s `updated_at`,
a `freshness(judge)` column, 14 tests, 114 lines of `ARCHITECTURE.md`, a session record and a
BACKLOG item — while master had none of it (`grep -rn BoardAbandoned --include=*.py` = 0) and
the class it judges grew from 18 rows to 19. Twelve days of every lane's mornings ran without
it. The first job was to land that work, not to redesign it: `git apply --3way` put the three
pipeline files down cleanly (only `cc4a493` had touched them since) and the tests conflicted
only as an append.

Three things the 08-30 branch could not have known, each found by landing it:

**1. The census blinds itself the morning the verdict ships.** `registry_health.stale_boards`
caught a bare `Exception` around `fetch_company`, and the verdict's whole mechanism is to
RAISE — so the tool that found this class would have reported **0** of it from the day the fix
landed. The 08-30 branch had filed this against itself and it would still have shipped, because
the filed diff and the change were in different trees. Fixed here, plus its sibling in
`region_report` (which now measures a refused board's postings off the exception rather than
skipping the row). And a second half the branch had not seen: the census and the mail would
then have disagreed for ever with neither wrong, because `_hosted_board_alive` spares a row the
dates condemn. The headline splits them — `SPARED` vs `REFUSED` — so the number this lane
reports is the number the mail will print.

**2. A module-level helper name is shared across 31,000 lines.** Appending the block made four
classifier-backfill tests fail with `assert (1 == 30)`: both lanes had written a `_bf_job`
helper, master's for a backfill job and the branch's for a board posting, and **Python resolves
a module-level name at call time, so the last definition silently steals every earlier caller.**
Neither author could have seen the other. Renamed to `_abnd_*`, and
`test_no_two_helpers_in_this_file_share_a_name` now refuses the class — it found a second,
older instance immediately: two byte-identical copies of
`test_the_blank_re_ask_has_a_wall_clock_bound_not_just_a_count`, of which **the first had never
run**. Deleted (28 lines).

**3. An empty `country_code` is not free.** `israel.is_israel_job` reads the country field first
and trusts a NON-Israeli one as a negative, so a fetcher that leaves it blank hands the decision
to the place-name scan — which does not know every Israeli town. Measured over **218 postings
and eleven live SuccessFactors tenants**: six real Israeli postings were being dropped as
foreign, four at `Shlomi, ISR, IL` (West Pharmaceutical) and two at `Bar Lev, IL, 20156`
(Dentsply Sirona), one of them an *Inventory & Logistics Analyst*. `_sf_country` reads the
country the tile states and **writes only `IL`**: +6 / −0 / 212 unchanged. The asymmetry is the
safety, not a shortcut — stamping a foreign token would give a fetcher the power to DELETE a
posting the text scan accepts, on a two-letter fragment that need not be a country at all
(`Ra'anana, ISR, IL` has two of them).

## 2. Cal is not an accordion — `594`, filed with the page measured

The hand-over from `registry` described accordion sections. One unlocker fetch of
`https://www.cal-online.co.il/about/jobs/` (103,679 bytes, **1 Bright Data credit**) contains
no `<details>`, no `<summary>`, no `accordion`, no `collapse`, no `aria-expanded`. It is 29
`<h3>` titles with no class, each beside a `<button data-job-id="JB-26544" …>` that opens a
CV-upload modal, so **no posting has an address of its own**. Three measurements:

1. `_CARD_PATTERNS`'s `{5,140}` counts ENTITY characters, and the page serves Hebrew as
   `&#x5E0;` — eight characters a letter. The heading pattern finds **18 headings on the served
   HTML and 38 on the same HTML unescaped**; the card group holds 11 of 29.
2. Ten of those eleven are dropped as locationless, because `_page_is_il` answers only under
   `SCRAPE_ASSUME_IL`, which `listing_hunt` sets and the 00:00 refresh does not. **That is why
   the row "verified ~30" at hunt time and yields 1 at night.** Its docstring says *"This
   function must never widen further"*, and it is right — so this is filed, not fixed.
3. The survivor carries `אילת` (Eilat), read from a byte window that reaches the next posting's
   city. The wrong city is what reaches the board and the mail.

## 5. Clause 4 — the questions, with the artefacts

**What did you delete or unify?** `git diff --stat origin/master...HEAD`: **+1,347 / −146**
across 14 files. Deleted: a shadowed 28-line test copy that had never run; a duplicated

**Which existing function did you extend, and which did you decline to duplicate?**
`health.stale_reason` (a new `error=` kwarg, so the reason is decided where every other reason
is), `fetchers.fetch_company` (the one entry point every writer already goes through — a second

already re-points a row through the identity gate with a twin-board refusal and an atomic
write, so the eleven conversions went through it; the park needed a tool that does not exist,
and it stayed a scratchpad script rather than becoming root module number 33.

**What design did you reject, and on what number?** Widening `_page_is_il` to rescue Cal's 29
postings: its docstring records that a page-level Israel signal let a nav menu with an Israeli
footer score as a board, and `SCRAPE_ASSUME_IL` exists because of it — so the 29 are filed
(`594`) rather than bought with that. Stamping a foreign `country_code` from a SuccessFactors
tile: +6 would have come with the power to delete any posting the text scan accepts, and the
measurement that justified the Israel-only rule (218 postings, 11 tenants, 0 losses) says
nothing about the foreign direction. And writing `defunct:` on Cybersixgill, whose careers page
embeds its acquirer's Workday board: one page is not two sources, and §8's rule 4 is that
CyberArk→PANW looked like a false match and was a real acquisition — so it is named in §4 above
and left to `registry`.

**Would the next session find this?** `grep -rn "abandoned" pipeline/` lands on
`health.abandoned` and `fetchers.BoardAbandoned` and nothing else; `registry_health.py
--stale-boards` prints the verdict's own words. `grep -n "_bf_job" tests/test_units.py` returns
one definition, and the guard that keeps it that way is named after the question.

**What did you make harder for the next lane?** Six things, counted: one exception class
(`BoardAbandoned`), one stale reason (`abandoned-board`) which is also a registry verdict token

(`_sf_country`) that a future platform author must know to imitate. The `abandoned-board` token
