## What changed

- `rolecard.display_name(rec, company, firmographics)` — THE derivation, one place.
  Refuses: non-str, empty, >60 chars (never truncated — a cut brand is a wrong name), LLM
  non-answers ("N/A", "unknown"…), entity-shaped text (`&rlm;` survives `_md_esc` and
  GitHub renders it), letterless strings, names NFKC rewrites (fullwidth/math-bold
  homoglyphs), identities of nothing or of single letters (Cyrillic-і "Wіx" → {w,x}), and
  **any name whose identity token-matches (equal or subset) a different company in the
  handed dict** — the impersonation guard; "Wix Analytics" is still Wix. Control/bidi/
  invisible chars stripped (whitespace collapsed BEFORE the strip: a newline is a
  separator, stripping first glued "Bounce\nAI"). Token index cached per dict
  (`_id_token_index`, lru; the scan is the NORMAL case for a renamed brand, ~5.5 ms/card
  uncached against the full 1,313-key export — wave 2's measurement — vs ~0.6 µs cached).
  Wave 2 also found the mixed-script escape the NFKC gate misses (a Cyrillic о inside a
  Latin brand: `identity_key` deletes the foreign letter, so "Mоnday.com" keyed to junk
  tokens and slipped the guard) — a Latin name carrying any Greek/Cyrillic letter is now
  refused outright (`_DN_FOREIGN`); whole-script names key to empty and were already
  refused; other-script mixes (Armenian, say) remain theoretical and unguarded.
- `_fill` derives once, stores `card["display_name"]` (default "" in `_LAST_RESORT` so
  every stub path carries the key), overrides `display_company`, appends the brand to the
  search blob. `cross_check`'s display-collision revert clears BOTH; a brand folding two
  registry rows onto one cell now alarms even when the raw names only differ by case
  (helfy/Helfy both "Helfy"); `also_listed_as` drops a claimant that IS the brand
  (`### Port.io _(also listed as Port.io)_` was the one live claimant shape).
- `build_markdown` builds every block first, runs `cross_check` ONCE above the headings
  (measured non-idempotent: call 2 returns `[]` after call 1's revert — a defensive second
  call would silently drop every display-collision), then emits; the heading reads the
  card's `display_name`, falling back to the RAW company (never `display_company` — the
  truncator would change today's mails). The board records who lost a brand to the revert
  (`display_demoted` on the render report) and the mail — a SUBSET population rendered
  last — demotes the same companies: one morning, one verdict on every surface.
- Board loop: `shown_co = c["display_name"] or company` for the About label and the
  Company sort key (`data-company`); the cell already rendered `display_company`, and its
  `title=` tooltip keeps the registry name as provenance everywhere.

## Rejected designs, with the number that killed each

- Candidate-key tuple ("display_name"/"brand"/…) — the contract was agreed live with the
  owning session; one key + one recorded contract beats speculative tolerance.
- Registry rename — 459's sequencing: a rename landing anywhere first orphans the
  firmographics and roles joins at the same instant.
- Title-casing the slug — the module comment beside `secrethunter.name_from_slug`
  (`secrethunter.py:159`) disclaims it: "evidence for a case-insensitive match, not a
  display string"; and inventing names is forbidden by the brief.
- `display_company` as the heading fallback — the truncator shortens taglines
  ("Oak - Identity Security OS" → "Oak"), so world A would change; raw-company fallback
  is what made `--golden` 6/6.
- Case/identity-folding `by_display`'s grouping — would move world-A output for
  ACME/Acme-class pairs; the identity guard covers the spoof without moving bytes.
- Passing the full 1,313-key export into render for the guard — file IO inside the pure
  card layer; the write-time check belongs to the lane that writes the field.
- `dn = jdtext._display_company(dn)` (1c) — the contract says brand-only; the splitter
  would mangle a legitimate " - "-carrying brand; CSS ellipsis handles width.
